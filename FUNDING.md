# Funding FXOTP

FXOTP (FXVN Open Trading Protocol) is an open-source project focused on
creating a simple, interoperable, and platform-independent format for
structured trading instructions.

Financial support helps sustain the development, documentation, testing,
security, tooling, and community infrastructure of the open-source FXOTP
project.

---

## Why FXOTP Accepts Funding

Building an open protocol requires more than maintaining a specification.

Funding may help support work such as:

- Protocol design and development
- Specification maintenance
- Documentation
- JSON Schema development
- Validation tools
- Test suites
- Compatibility testing
- Developer tooling
- Reference implementations
- Security review
- Open-source infrastructure
- Community support
- Educational material
- Interoperability testing
- Release engineering

The goal of funding is to help FXOTP remain useful, maintainable,
independent, and accessible to the open-source community.

---

## Open Protocol, Independent Implementations

FXOTP defines an open protocol.

Organizations and developers may build their own independent
implementations of the protocol subject to the applicable open-source
license and specifications.

An implementation of FXOTP does not need to use FXVNPro services.

FXVNPro may also develop commercial products and services that implement
or interact with FXOTP.

Those commercial implementations are separate from the open-source
FXOTP project unless their source code is explicitly published as part
of an FXOTP open-source repository.

## What FXOTP Funding Supports

Funding received specifically for FXOTP should support the open-source
project and activities that advance its open-source mission.

Examples may include:

### Protocol Development

Development and maintenance of:

- FXOTP specifications
- Message schemas
- Error models
- Compatibility rules
- Versioning rules
- Protocol extensions

### Documentation

Creation and maintenance of:

- Developer documentation
- Integration guides
- Examples
- Tutorials
- Compatibility documentation
- Migration documentation

### Testing and Quality

Work related to:

- Automated tests
- Conformance tests
- Validation tooling
- Compatibility testing

- Release testing

### Reference Tooling

Development of public tooling intended to help developers understand

Examples may include:

- Validators
- SDK helpers
- Test utilities
- Example applications
- Minimal reference implementations

Reference implementations should demonstrate the protocol without
requiring publication of proprietary production systems.

### Security

Funding may support:

- Security reviews

- Security documentation

### Community and Ecosystem

Funding may support activities such as:

- Contributor support
- Developer education
- Community documentation
- Open-source events
- Integration testing
- Ecosystem development

All spending should remain consistent with the requirements of the
applicable fiscal host and the open-source mission of FXOTP.

---

## What Sponsorship Does Not Buy

Financial support does not provide ownership or control of FXOTP.

Sponsors do not receive:

- Ownership of the FXOTP protocol
- Ownership of the FXOTP project
- Special control over technical decisions
- Special voting rights
- Guaranteed acceptance of proposed features
- Preferential protocol behavior
- Control over the public roadmap
- Access to private user information
- Access to credentials or security secrets
- Access to proprietary FXVNPro source code
- Access to proprietary FXVNPro infrastructure

Sponsors may participate in public technical discussions and propose
changes under the same contribution and governance processes available
to other participants.

Technical decisions should continue to prioritize interoperability,
security, simplicity, compatibility, and the long-term health of the
open protocol.

---

## FXOTP and FXVNPro

FXOTP and FXVNPro serve different roles.

### FXOTP

FXOTP is the open protocol layer.

It may include:

- Public specifications
- Public schemas
- Public examples
- Public validation tools
- Public tests
- Public documentation
- Public reference implementations

### FXVNPro

FXVNPro may operate independent commercial products, infrastructure,
services, integrations, and proprietary implementations that use FXOTP.

Examples may include commercial execution infrastructure, hosted
services, platform integrations, automation systems, data services,
and other products.

Unless explicitly released as open source, proprietary FXVNPro software,
infrastructure, data, algorithms, services, and implementation details
are not part of the FXOTP open-source project.

Funding FXOTP does not grant access to or ownership of these proprietary
FXVNPro assets.

---

## Public Protocol vs. Private Implementations

FXOTP is designed to make interoperability possible without requiring
implementations to disclose their internal systems.

For example, an FXOTP implementation may publicly accept a structured
instruction such as:

- Instrument: XAUUSD
- Action: BUY
- Order type: MARKET

The protocol may define how this instruction is represented.

However, an implementation is not required to disclose proprietary
systems used for:

- Signal processing
- Broker-specific mapping
- Routing
- Authentication
- Risk management
- Execution
- Infrastructure
- Monitoring
- Commercial services

This separation allows FXOTP to remain open while independent
implementations can compete and innovate.

## Financial Separation

Funding designated for the FXOTP open-source project should be treated
separately from ordinary commercial revenue generated by independent
FXVNPro products and services.

Examples of FXOTP project funding may include:

- Donations
- Open-source sponsorship
- Grants
- Community contributions
- Funding specifically designated for open-source FXOTP development

Examples of independent commercial activity may include:

- Commercial subscriptions
- Hosted services
- Commercial APIs
- Execution services
- Private integrations
- Commercial support agreements
- Proprietary products

The existence of a commercial implementation does not automatically make
its revenue or proprietary assets part of the FXOTP open-source project.

Any funds administered by a fiscal host remain subject to that fiscal
host's policies, legal requirements, and applicable agreements.

---

## Transparency

Where FXOTP funding is administered through a fiscal host, financial
activity may be publicly visible according to the fiscal host's
transparency policies.

The project intends to communicate clearly about:

- Funding received for FXOTP
- Major open-source spending
- Sponsored development when applicable
- Material conflicts of interest

Financial transparency does not require disclosure of security-sensitive
information, private personal information, credentials, or proprietary
implementation details.

---

## Conflicts of Interest

Contributors and maintainers should disclose relevant commercial
interests when proposing protocol changes that could materially benefit
a particular company, platform, broker, service, or implementation.

Commercial participation is welcome.

However, technical decisions should be evaluated primarily according to
their benefit to the protocol and its interoperability goals.

---

## Sponsor Recognition

FXOTP may publicly recognize organizations or individuals that support
the project.

Recognition may include:

- Sponsor listings
- Funding acknowledgements
- Release acknowledgements
- Project updates
- Website or documentation recognition

Sponsor recognition does not imply endorsement of a sponsor's products,
services, trading activities, or business practices.

Sponsorship also does not imply that a sponsor controls FXOTP.

---

## Independence

FXOTP should remain implementable by organizations that do not use
FXVNPro commercial services.

Likewise, FXVNPro and other organizations may build commercial products
using the open protocol.

The long-term objective is an ecosystem in which multiple independent
applications can understand the same FXOTP messages while competing on
their own technology, infrastructure, services, and user experience.

---

## Fiscal Hosting

FXOTP may use a fiscal host to receive and administer open-source project
funding.

A fiscal host may provide services such as:

- Fund administration
- Payment processing
- Accounting
- Invoicing
- Tax and compliance support
- Expense processing
- Contract administration

Funds held by a fiscal host remain subject to the fiscal host's policies,
agreements, legal requirements, and mission-related spending rules.

The use of a fiscal host does not by itself make unrelated proprietary
FXVNPro assets part of the FXOTP open-source repository.

---

## Questions

Questions about FXOTP funding, sponsorship, or project governance may be
raised through the project's public community and governance channels.

Questions involving security vulnerabilities should follow the process
described in `SECURITY.md`.

---

## Guiding Principle

Funding should help make FXOTP a better open protocol.

It should not provide a mechanism for any sponsor, vendor, broker,
platform, or commercial participant to purchase control of the protocol.
